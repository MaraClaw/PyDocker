# Documentation Agent Guide

## Sources And Page Wiring

- `docs/template/index.md` includes the root `README.md` through a snippets directive; edit the README for homepage content.
- `docs/autogen.py` owns the explicit `pages` mapping from output paths to API symbols.
- Add or rename pages in that mapping and `docs/mkdocs.yml`'s `nav` together.
- Arbitrary unmapped templates and assets aren't automatically copied into the output tree.
- `{{autogenerated}}` marks where API directives are inserted for the mapped symbols.
- Only a missing template triggers API-only fallback. An existing template without that marker gets no API directives.
- `@INSERT_GENERATED_CODE@` marks example output inside object templates; `docs/docs_utils.py` replaces it.
- Preserve the `TEMPLATE_FILES` alias: `docs/template/user_guide/running_pydocker_inside_a_container.md`
  produces `docs/generated_sources/user_guide/running_pywhales_inside_a_container.md`.

## Generation And Rendering

- Use the root guide's documentation-generation command from the repository root.
  Don't run `python docs/autogen.py` directly: it uses a relative import of `docs_utils`.
- `md_generate()` renders mapped templates and API directives; `add_links()` then rewrites links.
  `add_all_code_examples()` fills example markers before the generated tree is replaced.
- Rendering happens in a temporary staging directory beside `docs/generated_sources/`.
  Template or provider failure during rendering leaves the previous tree intact.
- After rendering succeeds, the generator deletes the old tree with `rmtree()` and renames the staged tree.
  This replacement isn't atomic; don't describe it as an atomic swap or retain hand-added output files.
- `docs/mkdocs.yml` reads `generated_sources` and writes `../site`, relative to the config file.
- Run MkDocs from the repository root, too: the homepage snippet resolves `README.md`,
  and `pymdownx.snippets` has `check_paths: true`, so a missing include fails the build.
- Follow the locked uv environment in `pyproject.toml` and `uv.lock`, as used by the `render-docs`
  job in `.github/workflows/python-package.yml`; `docs/requirements.txt` has older pins and isn't CI's dependency source.

## Offline And Live Examples

- Default generation inserts explanatory placeholders without calling live providers or Docker.
- `docs_utils.add_all_code_examples()` also defaults to offline behavior when called independently.
- `--live-examples` opts into all nine providers: plugins, configs, networks, volumes, images,
  containers, builders, nodes, and services. These require Docker; builders also use Buildx.
- Live providers can pull images, create resources, install a plugin, and initialize Swarm.
  Cleanup can remove acquired resources and leave a Swarm initialized by the examples. Use a disposable daemon.

## Focused Tests

All four modules are under `tests/pywhales/` and run without a real Docker daemon.

| Module | Coverage |
| --- | --- |
| `test_docs_generation.py` | Offline repeatability, markers, page mapping, fallback, stale-tree removal, staged-render failures, and mocked live dispatch. |
| `test_docs_live.py` | Mocked provider rendering, cleanup, borrowed state, and failure paths; not real-Docker integration. |
| `test_docs_acquisition.py` | Partial acquisitions, reused names, Swarm ownership, cleanup order, and volume formatting. |
| `test_docs_malformed_metadata.py` | Fake CLI responses with invalid inspection metadata; cleanup of owned resources and preservation of borrowed state. |

The `daemon` fixture in `tests/pywhales/conftest.py` supplies mocked Docker resources and rejects real
subprocess commands. Generation tests separately reject external commands; malformed-metadata tests stub the subprocess boundary.

```bash
uv run --locked pytest tests/pywhales/test_docs_generation.py \
  tests/pywhales/test_docs_live.py tests/pywhales/test_docs_acquisition.py \
  tests/pywhales/test_docs_malformed_metadata.py
```
